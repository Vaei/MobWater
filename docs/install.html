Install

Clone, build, set up, place a pool. UE 5.8+.

Get the plugin

Clone into your project's Plugins folder:

cd YourProject/Plugins
git clone git@github.com:Vaei/MobWater.git

Or, if your project is itself a git repository, as a submodule so the version is pinned:

git submodule add git@github.com:Vaei/MobWater.git Plugins/MobWater

No git: download the ZIP and extract it to YourProject/Plugins/MobWater.

Then regenerate project files and build. It carries a runtime and an editor C++ module, so the project has to be a C++ project - if yours is Blueprint only, add any C++ class once and Unreal converts it.

Project settings

Nothing here is checked at runtime. Config/DefaultEngine.ini, under [/Script/Engine.RendererSettings].

Scene depth in the translucent passthe one hard requirement. The bed, the water column, the shoreline foam and the caustics all come from it. Confirm it on your target platform before committing to any of this
Scene colour in the translucent passonly if Refraction is on. It is a per-body switch and it compiles the read out entirely, so a platform that will not copy scene colour is not a platform this is unusable on
r.Substrate=falsethe master is a legacy material graph
r.EarlyZPass=0no depth prepass, which is why fill is the whole cost model
Verify scene depth in the translucent pass on the platform you are shipping to, not in the editor. Without it every body of water reads a flat bed: no shoreline, no clarity, no caustics, and a colour that never grades.

Set it up

Enable the plugin, restart, then Water → Set Up Water on the level editor toolbar. It authors the parameter collection, the master, its thirty nine instances, the surface meshes, the tiling textures, the wave presets and the look presets, points the project settings at all of them, and refreshes any water already standing in the level.

The materials are generated rather than shipped, because they are output: Python/author_water.py and Shaders/ are the source. Generating is the only thing that wants the Python Editor Script Plugin, which this plugin enables for you. A project that never regenerates never loads Python.

Generate Materials is the same authoring step without the settings write or the refresh. Use it after editing a shader or a generator constant; use Set Up Water the first time.

Set Up Water writes to Config/DefaultEngine.ini. Under source control that file is usually read only, so it checks the file out first, and clears the flag if there is no source control provider to ask. Without that the settings apply for the session and are gone at the next restart, which reads as the setup not having worked rather than not having saved.

Place a body before generating and you get a notification naming the shape it could not find a material for, with a link that generates them.

Place a pool

  1. Drag a Water Pool out of the Water menu, or out of Place Actors → Mob Water, into a hollow.
  2. Set Extent to the size of the hollow and Depth to how deep the water is meant to be.
  3. Pick a Look Preset and press Apply Look Preset.
Size a body with Extent, never by scaling the actor. The component owns its own scale and sizes the unit mesh from the extent, and the vertex shader is told the half extent so it knows how far a vertex is from the bank. Scaling the actor tells it nothing.

Then make it interesting

Each is a tick box and each is a separate shader, so nothing you leave off costs anything.

Foamthe shoreline, the bank and the crests. On by default, and most of what makes water read as meeting something
Foam Texturethe foam carries a pattern of its own, in the shoreline's frame rather than the current's
Ripplesthe body reads the interactive field, so anything moving through it leaves rings
Refractionthe surface bends what is behind it. The one feature that reads scene colour
Toggling any of the four swaps the material. Something that has to fade its foam out should be left ticked and driven by Foam Opacity, not switched off at the bottom of the fade.

Characters in it

Add a Mob Water Interaction component to a character and it reports immersion, fires enter, exit and splash events, leaves ripples, and drives wade and swim over a stock UCharacterMovementComponent. Nothing is spawned for you - bind OnSplash to your own Niagara. See Characters in it.

Add a Mob Water Underwater component to a camera for the view from below. See Underwater.

Preview on the target

Set the preview platform to Android ES3.1 or PC D3D Mobile before judging anything. Water tuned under SM5 is water tuned twice.

Check it worked

  • The Water menu is on the level editor toolbar.
  • Water → Verify Contract passes. Results in the Output Log.
  • A placed pool grades from its shallow colour to its deep one as the bed drops away.
  • The surface moves in the viewport without playing.
  • mob.Water.Debug reports a non-zero tick count and a clock that is advancing.
