Under the hood

The contract between the component and the material, how the assets are built, and the traps that cost real time to find.

Custom primitive data

The component writes these and the material reads them. Nothing in the engine ties the index one writes to the index the other reads; they agree because two files say the same number, and Water → Verify Contract is what notices when one of them stops saying it.

There are thirty six of these and that is the engine's number, not a choice: FCustomPrimitiveData holds nine float4s. A write past the end is not an error, it is a no-op, and the material reads zero for the rest of the project's life with nothing said. MobWaterComponent.cpp carries a static_assert against the engine's constant so the next parameter that does not fit fails the build instead of failing silently.

Packing

Three slots carry two values each, because the array is full and each pair is one control rather than two. The whole number is the first value in hundredths and the fraction is the second:

Packed = round(A * 100) + clamp(B, 0, 0.999)
A      = floor(Packed) * 0.01
B      = frac(Packed)

It costs the first value a hundredth of precision, which is invisible on a slider clamped to 0-1, and it is why those sliders have the ranges they do. The alternative was a fourth parameter that silently did nothing.

In a game world these are written as runtime data. In the editor they are written as defaults as well, so a saved level draws correctly before it is ever played - and as runtime data at the same time, because the renderer reads the runtime array and a default only copies itself across when the default changes.

The wave writes happen only when the set changes, not every tick - seventeen vector writes a frame for a value that almost never moves would be the subsystem's whole cost. The names are centralised in one namespace because Python writes the same strings, and a rename that reaches one side and not the other produces water that renders perfectly flat with nothing in any log.

The shader library

Shaders/Public/, mapped to /MobWater. A pure function library: no .usf, no global shaders, no renderer code. Camera-relative throughout, because a UE5 world position is a large-world value that cannot be squared without losing it and the mobile pixel ALU is half precision besides.

MobWaterWaves.ushthe Gerstner sum. This file and MobWaterWaves.h are one algorithm written twice, and mob_water_verify.py asserts they agree
MobWaterSurface.ushdepth recovery, absorption, foam, shoreline frames, exclusion, caustics, glint, Fresnel, the packing helpers
MobWaterField.ushthe wave-equation step and reading the field back
MobWaterSpectrum.ushhow the baked sea state's atlas is addressed. This file and MobWaterSpectrum.h are one addressing scheme written twice, and the verify measures what is left between them

The maths lives there and is reached from Custom nodes, so the graph stays a thin wiring layer over readable HLSL rather than a wall of nodes.

Regenerating

Water → Generate Materials runs Python/author_water.py: the surface meshes, the generated textures, the parameter collection, the master, its ninety two instances, the ripple materials, the underwater material, the wave presets, the look presets and the colour ramps. Set Up Water is the same thing plus writing the project settings and refreshing placed water.

Water → Bake Ocean Spectrum is separate, and runs Python/mob_water_spectrum.py. A generate only runs it when there is no sea state at all, because nothing about authoring materials changes the sea and a solve is seconds rather than an instant. The bake parameters are constants at the top of that file.

Run it once after installing, and again after editing anything in Shaders/ or a generator constant.

Every phase is idempotent: an existing asset is emptied and rebuilt in place, so placed bodies keep their references and re-running is always safe.

The master and its instances are not versioned - Content/Materials/ is gitignored. They are output: the .ush files and the builder are the source, a regenerate rewrites every one of them, and a shipped copy can silently drift from the shader it was built against. Content/Meshes, Content/Textures, Content/Waves and Content/Looks are versioned, because the settings name them by soft path and a clone without them has dangling references rather than water that has not been generated yet.

The collection is the exception

MPC_MobWater is not rebuilt the way the materials are. Rebuilding it would issue new GUIDs, and every material referencing the old ones would silently compile them as zero. The generator adds any missing parameter, prunes any the materials no longer read, and touches nothing else - a parameter left behind in there is a knob wired to nothing that reads as a knob wired to something.

Verifying

mob_water_verify.py asserts the claims one at a time, so a failure names the claim that stopped being true:

  • The constants in MobWaterWaves.h match the defines in MobWaterWaves.ush.
  • Every MobWaterData index matches the parameter index in the material, and none is at or past thirty six.
  • The CPU evaluator and the shader agree, at 192 points across 3 instants. Worst disagreement to date: 0.00074 cm.
  • The baked sea's table and its atlas agree, the same way. Worst to date: 0.05458 cm - looser on purpose, because that comparison is a hardware bilinear filter against a software one and a filter's subtexel weights are fixed point.
  • The generated content is the version this build expects.
Run headlessly, the version check reports six assets missing that plainly exist. The asset registry has not scanned in a commandlet, so the existence check answers no for a folder that is full - the same trap the generator works around by loading assets rather than asking about them. It passes in the editor.

Gotchas

These each cost real time to find.

Custom primitive data past index 35 is silently discardednot an error, a no-op. Three parameters were added, wrote past the end, and read as zero for weeks while every setting looked correct in the details panel
does_asset_exist lies in a commandletit reads the asset registry, and a registry that has not scanned answers no for assets that are plainly there. The create call then fails, because it cannot prompt about overwriting with nobody watching. Load the asset instead of asking about it
An import that names no factory goes through Interchange, and Interchange deadlocks a generateInterchange runs the import on worker threads and waits for them from the thread that asked. One worker calls FApp::GetCurrentTime, whose IsInGameThread ensure prints a script callstack, which needs a lock the waiting game thread holds. The editor stops on the first texture, with no assert and no dialog. A commandlet survives it, so it reads as broken content rather than a broken call. Naming TextureFactory on the task is the whole fix: UAssetToolsImpl only routes through Interchange when no factory was given
delete_all_material_expressions_in_function leaves nodes behindso re-running a builder accumulates duplicate function inputs, and the caller's connections land on whichever copy the name lookup hits first. Loop until the graph is actually empty
A Custom node cannot use a shared samplerand the sixteen sampler budget is what binds on this renderer. Every tap therefore happens in a TextureSample node set to Shared:Wrap, and the maths takes already-sampled values
A Custom node emits its whole body regardless of what reads itso an unused branch is not free. Gate with static bool function inputs, not with an if on a value
Editing a .ush needs an editor restartnot recompileshaders changed. That command does not pick up a .ush under a plugin's virtual shader path, and the material carries on running the shader it already had, with no error and no warning
Rebuilding a parameter collection reissues its GUIDsand every material referencing the old ones compiles them as zero. Additive plus a prune, never a rebuild
The graph is laid out to the left of the originthe material's output node sits at zero and cannot be moved, so numbering columns upwards from zero puts the whole graph to the right of the thing it feeds and every wire runs backwards
A material instance validates every texture parameter's sampler typeincluding ones in a branch a static switch compiled away. A failed instance renders black rather than reporting anything
Foam that only replaces base colour is not foamthe wave normal, the sun glint and the sky reflection all keep shading through it, and it reads as a white texture painted onto moving water. Foam has to suppress all three
A vertex shader cannot read the depth bufferwhich is why wave attenuation is weighted by distance to the body's own edge and not by how deep the water is. The edge is arithmetic, so the vertex shader and the CPU query can both have it
The shared wrap sampler is anisotropicwhich is fine for a tiling texture and wrong for a frame atlas: at a grazing angle it widens its footprint past the cell and averages in the neighbouring frame, and an average of several frames of a travelling wave comes to nothing. It read as the sea flattening towards the horizon. Naming an explicit mip level makes a widening filter impossible, and settles the vertex shader's own question at the same time - there are no derivatives there, so a sample with no level named is a level the compiler has to invent
A TextureSample has no float4 output that can be connected by namethe unnamed one is RGB, and RGBA does not resolve. Handing it to a Custom node whose parameter is a float4 fails inside the generated material with "cannot implicitly convert from float3 to float4", pointing at a line of HLSL nobody wrote. Append the alpha back on with an AppendVector
A texture with frames laid out in it needs a gutter and no mipsthe field wraps and the atlas does not, so every cell carries a one texel copy of its own opposite edge. Without it the filter reads the next frame at every tile boundary - a band one texel wide across the whole ocean, which looks like a compression artefact. Mips are worse: the second one averages one frame with the next and every mip past it is more of that
A VisibleAnywhere property cannot be set from Pythonit carries CPF_EditConst, and the binding refuses. A record that a bake writes and nobody may edit therefore needs a function to write it, which is the better shape anyway - a sea state whose stated wind is not the wind it was solved at is worse than one that states nothing
The body a point is in is decided by height, not by depthdepth alone is right for two bodies at the same level - a shallow trough across a lake is decoration on it - and wrong the moment they are at different heights. A rock pool on a headland sits inside an ocean's footprint, so the deeper of the two answered about the sea two hundred metres below and everything put in the pool fell through it
A body with no wave preset took the world's, and the world's is a pondso an ocean placed before it had a preset, or with one cleared, ran pond waves and read as an ocean with its amplitude turned down. The shape's own default in the settings is consulted first now
CalcBounds(FTransform::Identity) measures the mesh, not the thing in the levelso pontoons built from it sat inside a scaled-up hull with a radius too small to reach the surface. Pass the component's own transform, then divide the extent back out of the scale - the offsets go through that transform again every tick
Containment cannot go through the component's scalea box and a disc are unit meshes stretched to their extent; an ocean's ring is built at world size already. A reading that divided by the scale and multiplied by the extent was right for the first two and out by the extent for the third, so the ocean answered that every point in the level was outside it - and nothing floated on the sea
Phase has to be folded on both terms before they meeta world position a kilometre out times a wave number is thousands of radians, and a float has about seven digits. Unfolded, the surface reads as faceted far from the origin and smooth near it
