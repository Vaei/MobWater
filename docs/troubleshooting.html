If it is wrong

Symptom to cause, in order of likelihood.

Nothing renders

SymptomCause
Nothing renders at allthe shape has no material. LogMobWater says so by name, once; Water → Set Up Water fixes it
A notification about a missing materiala body was placed before generating. The link on the toast generates them
Changing a feature tick box does nothingit swaps the material, so that combination has to exist. Regenerate
Water renders but the bed is flat everywherescene depth in the translucent pass is not available. That is the one hard requirement, and the editor having it does not mean the device does
Water renders blackan instance failed to compile. Usually a texture parameter whose compression does not match the slot - a material instance validates every texture parameter, including ones a static switch compiled away

The surface

SymptomCause
It never movesthe parameter collection was never written. mob.Water.Debug reports collection none - water will be flat
It moves in game and not in the viewportit should do both; the subsystem ticks in editor. If not, the level has no water subsystem, which means no world of a supported type
An ocean carries the wrong seaits Spectrum. Each ocean draws the one it is set to, and one with none set draws no baked sea at all - only its wave preset
A pond has an ocean's swellits Wave Preset. A newly placed body takes the preset for its shape, and one that was duplicated from an ocean did not
Waves stand above dry ground at the rimShore Fade Distance too short for the wavelength. It has to be longer than the waves it is putting down
The surface reads as faceted far from the originshould not happen - both phase terms are folded for exactly this. If it does, a wave under a centimetre long is in the set
A green cast, or dark blotches drifting with the surfacethe skylight, and waves turning away from the sun. Unlit
It reads as varnishedReflection Strength. A Fresnel reflection is a smooth ramp across the whole body
Deep water is the wrong colour over a pale floorcorrect, and the point. Colour comes from the column between the surface and the real bed
A shallow pool stays transparent however low the claritythere is almost no water in it. Min Opacity is the answer, not clarity
Water sits at the wrong heightthe actor's Z. Depth is what a query is told, not where the surface is
Resizing the actor did nothing usefulExtent, never actor scale. The component owns its own scale and the vertex shader is handed the half extent

Foam

SymptomCause
Foam covers the whole bodyShore Foam Depth anywhere near how deep the water actually is. It is a line, not a region
Foam looks like a broken texturethe same thing. What reads as texture is the noise applied over a region instead of along an edge
Bands are mottled blotchesbanding applied to a wide foam region. Narrow it first; bands only work once the foam is already a line
Bands look like one band with steps in itFoam Band Separation at 0. Nothing separates them
The foam is textured and should not beFoam Texture Opacity. With Foam Texture off it is how much of the water underneath shows through, and at 0 the foam is flat froth
Foam texture streaks the wrong wayit is sampled in the shoreline's frame, so it runs away from the bank on every side. If it runs with the current, Foam Texture is off and the water's own texture is showing through
Assigning a Foam Texture did nothingthe asset is a per-body override that takes a dynamic material instance. Confirm with Water → Open Selected Body's Material which instance the body is drawing
Turning foam off left a white edgea different source. Four feed it: shoreline, edge, crest and ripple
A still pond has no crest foamcorrect. Crest foam needs steepness a still body does not have, which is why it reads as still

Ripples

SymptomCause
A disturber does nothingthe body has Ripples off, or the disturber is outside the field - the field follows the view, and a body across the level is not in it
A permanent mound under a standing characterMove Threshold at 0 with Persistent on. The accumulated push builds
The field fills with noise that never settlesRipple Speed raised past stability. It is clamped at 0.45 for this reason
The pond never goes stillRipple Damping at 1
Ripples are coarseRipple Extent against a fixed 256². Reach and fineness trade directly
Buoyancy ignores a wakecorrect, and permanent. The field is a render target and a dedicated server has none - see the field is never authoritative

Exclusion

SymptomCause
A fifth volume holds nothing backfour are rendered at once, nearest the view. The log says so once
A distant hull fills with waterthe same. The CPU query answers from all of them, so it and the pixels disagree - the query is right
Water is on a bridge deck over a lakeexclusion is a footprint, not a storey. Inherent
A mesh exclusion behaves as a rectangleno outline was baked, and it says so once. Set Exclusion Mesh, or put the component on an actor that has a static mesh
A mesh exclusion cuts nothingit reaches only as far as its window does, and four are carried at once. mob.Water.Debug reports how many outlines are registered, how many have a mask, and where the window is
A character in a carved hull still counts as swimmingthe volume has Blocks Submersion off. With it on, the query answers no water there

Characters

SymptomCause
No splashnothing is bound to OnSplash. The component spawns nothing by design
Splashes only on entry, never on footfallscall Splash from a footstep notify. The component cannot know when a foot lands
The character is permanently slower after a puddlean override that reads the walk speed back after scaling it. Capture the original once
Wading or swimming does nothingthe project does not use a stock UCharacterMovementComponent. Override ApplyWade and ApplySwimming, and call nothing in the parent
Immersion is measured at the headMeasure Offset. It defaults to the feet of a standard capsule

Networking

SymptomCause
Two machines disagree about the surfacethe clock. Record both with -trace=default,MobWater and scrub the Water track together - there are only three lines on it and one of them will have parted
The surface jumpsthe engine fallback clock, corrected in steps. A step in the clock is a step in every wave at once. Bind a synchronised source
They agree on the clock and still disagreethey asked about different places. mob.Water.TraceQueries 1 puts the query point on the track beside the answer, which is the only way to tell that from a water bug
A character on a boat is in the wrong wateralmost never the water. Its query point comes off the hull's transform, so a small error there is a large one at the feet. Compare the boat's track, not the character's
Ripples and foam are on one machine and not the otherinherent, and not a bug. They live in a render target a dedicated server has no GPU to hold. Nothing about them is on the track for that reason
Physics sits slightly off the water it is drawn onsomething read the world's time rather than GetWaterTime. Only the folded value is allowed downstream

Editor

SymptomCause
Set Up Water is forgotten at every restartthe config file was not checked out. It checks out, and clears the read-only flag when there is no provider - if that is still failing, the file is locked by something else
Editing a .ush changed nothingrecompileshaders changed does not pick up a .ush under a plugin's virtual shader path. Restart the editor
Generate Materials does nothingthe Python Editor Script Plugin. The plugin enables it, but a project that disabled it by hand stays disabled
The Water menu is goneHide This Menu. Editor Preferences puts it back, and the choice is per developer rather than the project's
Verify Contract reports six assets missing that plainly existrun headlessly. The asset registry has not scanned in a commandlet, so the existence check answers no for a folder that is full. It passes in the editor
Pointing a shape at a new material left the level blanka component picks its material up when it registers. The settings refresh placed water for this reason; if it was changed another way, reload the level
